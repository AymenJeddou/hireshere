Chapter 16The browser code: search, filters, saved jobs

The search page filters about 12,000 jobs instantly, in the visitor's browser, without a server. This chapter walks through the TypeScript in site/src/scripts/.

Finding the visitor's country (country.ts)

{{js site/src/scripts/country.ts visitorCountry}}

Priority order: ?c= in the URL (shared links), then the visitor's last choice (localStorage), then the country seen earlier this session, and finally /api/geo, a one-line Function returning the country Cloudflare detects from the IP address. The choice is mirrored in a cookie (remember()) so server-rendered job pages can read it too.

Verdict for a country (cards.ts)

{{js site/src/scripts/cards.ts groupFor}} {{js site/src/scripts/cards.ts verdictsFor}}

The same "find my group, else the star group" logic as in the Python export, now in TypeScript. With no country selected, a job shows if it is open anywhere.

Drawing a card

{{js site/src/scripts/cards.ts card}}

Cards are built as HTML strings. Every value from the data goes through esc(), which turns < > & " ' into entities: job titles come from third parties, and inserting them raw would let a malicious posting inject script into the page (an XSS attack).

{{js site/src/scripts/cards.ts dateTag}}

The search engine (search.ts)

initSearch() loads the index for the page's language, works out the visitor's country, and keeps the state (query, country, filters, sort, page) in the URL, so every view can be shared or bookmarked. The core is one function that decides whether a card passes the current filters:

{{js site/src/scripts/search.ts passes}}

The optional skip argument powers the live counts next to each filter: to show how many results "Data" would give, count the cards that pass every filter except the field filter. That is how a filter panel can say "Data (5)" before you click it.

Words in the query must all appear in the title or company (lower-cased). Sorting is "best match" (verdict rank, then newest) or "newest first" by the employer's date. Twenty results per page.

Saved jobs and the tracker (saved.ts, profile.ts)

{{js site/src/scripts/saved.ts initSaveButtons}}

Saved jobs and their status (saved, applied, interview, offer, rejected) live in localStorage, in the browser only: no account, nothing on the server. Every access is wrapped in try, because private browsing can block storage, and the site must keep working.

{{js site/src/scripts/profile.ts languagesFit}}

Maps (worldmap.ts)

{{js site/src/scripts/worldmap.ts colourMap}}

public/world.svg has one <path id="TN"> per country. The home page colours each country by how many jobs are open to it; a job page colours it by verdict, with the visitor in coral. zoomTo() changes the SVG viewBox to frame one country.
