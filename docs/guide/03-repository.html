Chapter 4The repository, file by file

The repository has two halves: pipeline/ (Python, runs in GitHub Actions) and site/ (Astro and Cloudflare Functions). They meet in a handful of JSON files that the pipeline writes and the site reads.

The contract between the two halves

The pipeline and the website never import each other's code. They communicate through files written by python -m pipeline.run export:

FileRead byContents
site/src/data/meta.jsonAstro at build time, FunctionsUpdate time, product name, domain, counts, featured countries with verdict counts, all 243 countries with names and regions.
site/src/data/companies.jsonAstro at build timeOne entry per company: name, website, number of jobs, intern/junior count, countries named in its postings.
site/public/data/search-<lang>.jsonThe browserOne compact record per listed job (about 12,000), with verdict groups and reasons in that language.
site/public/data/j/<xx>.jsonJob page Function, browser fallback256 shards with each job's full details, same-company and similar jobs.
Why a file contract?

Because the two halves run in different places: the pipeline in GitHub Actions with Python, the site in the browser and on Cloudflare with JavaScript. Plain JSON files are the simplest thing both sides understand, they can be inspected with any text editor, and the site can be rebuilt from them without touching the database.

Documentation you should know about

  • docs/DECISIONS.md: a dated log of every significant decision and its reason. When you wonder "why is it like this?", look there first.
  • docs/SPEC.md: the original brief. docs/ROADMAP.md: what is done and what is open.
  • CLAUDE.md: the owner's rules and the main commands. DESIGN.md: colours, type and components. PRODUCT.md: who the product is for.
