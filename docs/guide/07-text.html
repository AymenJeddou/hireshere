Chapter 8Cleaning text and dates

Every feed formats things differently. Two small helpers in pipeline/text.py turn HTML descriptions into readable text and any date format into one standard form.

HTML to text with the standard library

Instead of a heavy HTML library, a subclass of Python's built-in HTMLParser collects text and inserts line breaks around block elements:

{{py pipeline/text.py _Stripper}} {{py pipeline/text.py html_to_text}}
  • Script and style contents are dropped (self.skip counts nesting).
  • Block tags (p, div, li…) become line breaks; list items get a "- " prefix, so the AI still sees the structure.
  • Regular expressions then collapse spaces and keep at most one blank line.

Dates from any feed

{{py pipeline/text.py iso_date}}

Feeds send ISO dates with offsets (2026-08-17T14:44:07-04:00), with a trailing Z, with " UTC", as a plain date, or as milliseconds since 1970 (Lever). Everything becomes an ISO 8601 string in UTC, so dates sort correctly as text and compare across sources. Bad input returns None rather than crashing the fetch.

Try it

In a Python shell from the repository: from pipeline.text import iso_date, then iso_date(1782214185805) and iso_date("2026-10-05 16:05:18 UTC"). The test file tests/test_text.py lists every format it must handle.

Why the employer's date matters

Before posted_at existed, the site showed "found 2 days ago", the date HiresHere first saw a job. The first real fetch showed that 47% of open jobs had been posted more than two months earlier (some in 2016). Now cards say "Posted n days ago", sorting uses that date, postings older than 60 days are drawn muted, and alerts and Telegram only announce jobs posted in the last 14 days.
