Chapter 17Cloudflare: Pages, Functions, D1 and the edge

Cloudflare serves hireshere.app from data centres around the world. Static files cost nothing and have no limit; Functions (server code) are free up to 100,000 calls a day. Knowing which is which is the key to this chapter.

The day job pages broke

Without this file, the middleware ran on every request: each image, logo, stylesheet and data file. One page view cost 20 or more Function calls, crawlers walked the 37,000 job URLs, and the free 100,000 a day ran out. Cloudflare then "fails open": it stops running Functions and serves only static files, so every job page showed the 404 page. Limiting Functions to /jobs/* and /api/* made a page view cost one call.

Static redirects: _redirects

{{lines site/public/_redirects 1-6}} {{lines site/public/_redirects 38-43}}

Old addresses from before the worldwide search (/tn, /fr/ma/engineering) redirect with a 301 (permanent) to the search with the right filters. The last three lines are a fallback: if Functions are ever off, job URLs serve the static page shell instead of a 404 (status 200 means "rewrite": the URL stays, the content comes from the shell). When Functions run, they take these paths first. The www to hireshere.app redirect is a Cloudflare Redirect Rule, configured in the dashboard.

Job pages on request (functions/_job.js)

{{js site/functions/_job.js handler}}
  1. Validate the slug with a regular expression (never trust the URL).
  2. Fetch its shard from the static files (env.ASSETS.fetch, which costs no Function call).
  3. Unknown slug: the job closed. Answer 410 Gone with the "This job has closed" page, which suggests similar open jobs.
  4. Work out the visitor's country: ?c=, then the cookie, then Cloudflare's guess (request.cf.country).
  5. Take the static shell for the language and replace its placeholders with the job's title, description and the rendered body (jobPage(), shared with the browser). Replacement functions are used because job text may contain $, which string replacement would interpret.
{{file site/functions/jobs/[slug].js}}

The browser fallback

{{lines site/src/pages/shell/[lang].astro 26-48}}

If the shell arrives with its slot still empty (no Function ran), the browser fetches the shard and renders the same page itself. Visitors never notice; only search engines get a slightly weaker page until Functions return.

The API endpoints (functions/api/)

EndpointDoes
POST /api/subscribeValidates and stores an alert subscription in D1; sends the welcome email.
GET/POST /api/unsubscribeChecks the HMAC token and deletes the subscriber (the POST form is the one-click button in mail apps).
POST /api/reportStores a "wrong verdict / job closed" report from a job page.
POST /api/employerStores an employer's request to be listed, reviewed by hand.
GET /api/geoReturns the visitor's country code as Cloudflare sees it.

Inputs are always validated on the server (allowed countries, fields, lengths), whatever the browser form already checked.

The D1 database (site/schema.sql)

{{file site/schema.sql}}

Queries use prepared statements with ? placeholders and .bind(), never string concatenation, which rules out SQL injection. From your computer: npx wrangler d1 execute hireshere --remote --command "SELECT count(*) FROM subscribers".

Other Cloudflare pieces

  • Web Analytics: visits, page views, referrers and Core Web Vitals (load speed, layout shift), without cookies.
  • Email Routing: contact@hireshere.app forwards to the owner's inbox.
  • Pages secrets: UNSUBSCRIBE_SECRET and RESEND_API_KEY, available to Functions as env.X.
