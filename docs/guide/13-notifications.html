Chapter 14Email alerts, welcome email and Telegram

People can get new jobs delivered: a daily email digest per country (and optional field), a welcome email when they subscribe, and four Telegram channels. All three must never send the same job twice, never spam, and always offer a one-click way out.

Signing up (site/functions/api/subscribe.js)

{{file site/functions/api/subscribe.js}}
  • A hidden honeypot field called "website": humans never fill it, bots usually do, so such sign-ups are dropped silently.
  • INSERT OR IGNORE with the primary key (email, country, field) makes repeated sign-ups harmless.
  • Only a truly new row (res.meta.changes) triggers the welcome email, sent with waitUntil: after the answer has gone back to the browser, so the form stays fast and a failed send can never break the sign-up.

The welcome email (site/functions/api/_welcome.js)

{{js site/functions/api/_welcome.js render}}

It explains what to expect (one email a day, only when new jobs open to their country appear), links to today's jobs, and includes the unsubscribe link. French sentences are worded so they are grammatical for every country name.

Unsubscribe links that cannot be forged

The link carries the email and a token: an HMAC (keyed hash) of the email made with a secret only the server knows. Anyone can see the link, but nobody can compute a valid token for someone else's address. The pipeline (Python) and the Function (JavaScript) produce identical tokens:

{{py pipeline/alerts.py unsubscribe_token}} {{js site/functions/api/unsubscribe.js remove}}

Emails also carry List-Unsubscribe and List-Unsubscribe-Post headers, so Gmail and others show their own one-click "Unsubscribe" button (RFC 8058).

The daily digest (pipeline/alerts.py)

Which jobs are "new" for a subscriber? Those that appeared on the site since their last digest. A job classified today from the backlog counts as new today, even if it was first fetched last week:

{{py pipeline/alerts.py visible_since}} {{py pipeline/alerts.py pick}} {{py pipeline/alerts.py due}}

due() guarantees at most one digest per UTC day, however many times the pipeline runs. It compares calendar days, not hours: an earlier 20-hour rule skipped subscribers when GitHub started a scheduled run late after a manual one. fresh() (in export.py) keeps out jobs posted more than 14 days ago, so adding a new company does not flood people with its old postings. Resend's free plan allows 100 emails a day; the code stops at 95 and leaves the rest for the next run.

{{py pipeline/alerts.py render}}

Telegram (pipeline/telegram.py)

{{py pipeline/telegram.py message}}

Each featured country has a private channel; the bot is an admin of each. Posted jobs are recorded in the telegram_posts table. On a channel's very first run only the newest five jobs are posted and the rest marked as seen, so a new channel is not flooded; after that at most 15 per run.
