Chapter 5Configuration: countries, boards, secrets

Three kinds of configuration drive the pipeline: constants in pipeline/config.py, data files (countries.json, boards.csv), and secrets passed as environment variables. A rule of the project: countries and names are configuration, never if country == "TN" branches in the code.

pipeline/config.py

The single source of truth for the product name, the domain, how politely to fetch, and the AI settings. Nothing else hard-codes "HiresHere" or "hireshere.app": the site even receives the domain through the exported meta.json.

{{lines pipeline/config.py 1-20}}

USER_AGENT identifies the bot honestly to every job feed, with a link back to the site. MAX_CONCURRENCY = 5 means at most five feeds are downloaded at the same time, so no company's server is hammered. ROLLING_DAYS handles feeds that only list recent jobs (Jobicy): a job that disappears from such a feed may still be open, so it only expires 30 days after it was posted.

Featured countries and the world

COUNTRIES lists the four featured countries (Tunisia, Morocco, Algeria, Egypt) with names in three languages, one UTC offset and the region names that include them. WORLD merges every country from data/countries.json with those featured entries:

{{py pipeline/config.py WORLD}}

This is a dict comprehension with the merge operator |: for each country in the JSON file, start from its entry and overlay the featured entry if there is one. Featured countries therefore keep their single utc_offset, which kept their verdicts stable when the site went worldwide.

data/countries.json

243 entries keyed by ISO 3166-1 alpha-2 code. Each has names in English, French and Arabic, the regions it belongs to (used to match postings that say "EMEA" or "LATAM"), and the range of UTC offsets its time zones cover (from the IANA time zone database). Example:

{{lines data/countries.json 2869-2882}}

The tz range matters for countries with several time zones: a posting that requires "US hours" (UTC-10 to UTC-5) fits Brazil (UTC-5 to UTC-2) because the ranges overlap.

The AI settings

{{lines pipeline/config.py 64-75}}

Every value that might change between environments is read from an environment variable with a default (os.environ.get("GEMINI_RPM", "0")). The daily workflow sets the pacing; local runs use the defaults. MAX_USD_WITHOUT_CONFIRM is a safety net from the paid era: a batch estimated above $5 does not start without --yes.

data/boards.csv: the company list

{{lines data/boards.csv 1-6}}

One row per company board: which ATS, the board's slug on that ATS (as in boards.greenhouse.io/doximity), the company's display name, its website (used for logos) and where the entry came from. The list is built and validated by pipeline/seed.py (chapter 9). Removing a row retires the board: its open jobs are expired on the next run.

Secrets and environment variables

Secrets never go into git. Locally they live in .env (ignored by git); in GitHub Actions they are repository secrets; for the Pages Functions they are Cloudflare Pages secrets. .env.example documents every variable:

{{file .env.example}}

For local runs, pipeline/run.py loads .env with a ten-line parser instead of a library. Real environment variables win, so CI settings are never overridden by a stray local file:

{{py pipeline/run.py load_dotenv}}
