Chapter 15The website: Astro, pages and languages

The site is built with Astro into plain HTML, CSS and a little JavaScript. Most pages are generated once at build time; job pages are filled in by a Cloudflare Function on request. Everything exists in English, French and Arabic.

How Astro works

An .astro file has two parts: a frontmatter block between --- lines, which runs at build time (on your computer or in CI, never in the visitor's browser), and an HTML template that can use its variables. Components are imported like functions. At build time Astro runs every page and writes static .html files to dist/. A <script> inside a component is bundled and runs in the browser.

{{file site/astro.config.mjs}}

build.format: "file" writes /jobs.html instead of /jobs/index.html, and trailingSlash: "never" keeps URLs clean. The domain comes from the exported meta.json, so it is defined once, in the Python config.

Pages and routes

Each file under src/pages/ is a URL. French and Arabic versions live under fr/ and ar/, with translated slugs (/fr/entreprises, /fr/a-propos). A page is usually three lines: pick the language, wrap a shared component in the layout.

{{file site/src/pages/jobs.astro}}

Dynamic routes such as companies/[key].astro export getStaticPaths(), which returns one entry per company; Astro builds a page for each:

Build-time data (site/src/data.ts)

{{file site/src/data.ts}}

Importing a JSON file in Astro reads it at build time. Lists, counts, company pages and the sitemap come from here; the browser loads the search index separately.

Three languages (src/i18n.ts, src/i18n-ar.ts)

Every piece of interface text is a key in a dictionary per language. tr(lang, key, vars) looks it up and fills {placeholders}; href(lang, page) builds the right URL for a page in a language:

{{js site/src/i18n.ts href}} {{js site/src/i18n.ts tr}}

The French dictionary is typed typeof en, so TypeScript reports a missing translation. Arabic pages set dir="rtl" on <html>, and the CSS uses logical properties (padding-inline-start, inset-inline-end) so layouts mirror automatically.

The layout (src/layouts/Layout.astro)

Every page goes through one layout: the <head> with title, description, canonical URL and hreflang alternates (so Google knows the three language versions are the same page), Open Graph tags for link previews, the header with navigation, the "Your country" select and language switch, and the footer.

{{lines site/src/layouts/Layout.astro 24-31}}

The tiny inline script adds a js class before anything is drawn. CSS uses it to reserve room for the cards and maps that scripts render later, which prevents layout shift (content jumping while loading).

The design system

styles/global.css defines design tokens as CSS custom properties (colours like --brand: #0b3a53, --accent: #ff7a59, the verdict colours, spacing and type steps) and base styles; styles/components.css styles cards, pills, filters, job pages. DESIGN.md documents the rules: verdict colours are only used for verdicts, the accent never is, every button is at least 44 px tall for touch.
