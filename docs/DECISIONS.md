# Decisions

Short log, newest last. Format: date, decision, why.

**2026-10-08. Plain asyncio + httpx, no framework.** One semaphore (5) caps concurrency. `pipeline/http.py` is the only place that talks to the network, so retries, timeout and User-Agent live in one spot.

**2026-10-08. Connectors split into `parse(data, board)` and `fetch(client, board)`.** Parsing is pure and tested against saved live responses in `tests/fixtures`. CI never touches the network.

**2026-10-08. HTML stripped with the stdlib `html.parser`.** No BeautifulSoup. Greenhouse `content` is entity-escaped HTML, so it is unescaped once before stripping.

**2026-10-08. Any connector exception means "fetch failed", never "board is empty".** `FetchError`, `KeyError`, `TypeError` and `ValueError` (unexpected shape) all go down the failure path, which expires nothing (rule 3).

**2026-10-08. Two extra columns on `boards`: `source_of_entry` and `last_error`.** Provenance of each seed entry, and why a board is failing, are visible in the database without digging through logs.

**2026-10-08. Re-seeding never resurrects a deactivated board.** `sync_boards` updates names but keeps `active` and the failure counter. To revive a board, set `active = 1` by hand.

**2026-10-08. SmartRecruiters: paginate, no description, cap at 1000 postings.** The list endpoint returns 100 postings per page and no description. Paging is the only way to get the full list (needed so expiry is correct), so this source breaks the "one request per board" rule by necessity. Boards above 10 pages are treated as failures and dropped by `seed validate`: they are large on-site corporates and a poor fit. Descriptions will be fetched per posting in Phase 2, only for candidates.

**2026-10-08. Ashby `isRemote` and `workplaceType` are often null.** `remote_flag_raw` stays null in that case; the location text ("Remote, Bay Area, CA") carries the signal. The classifier reads both.

**2026-10-08. Seed list sources and licenses.**
- `remoteintech/remote-jobs` is ISC licensed (the brief said CC0; the repo LICENSE says ISC). Permissive, we keep the notice in `data/CREDITS.md`. We take company name, website and careers URL.
- `kalil0321/ats-scrapers` is MIT; the root LICENSE covers `ats-companies/` and there is no separate data license. We take `name,slug` pairs.
- Mapping order per company: careers URL that points at a known ATS, then exact normalized name or slug match in ats-scrapers, then a cheap live probe of slug guesses. The match method is stored in `source_of_entry`.
- Top-up from ats-scrapers inventories (`source_of_entry = ats-scrapers`) is kept only when the board has at least one job whose location or remote flag looks remote.
- Name matches can be wrong when two companies share a name. Accepted for Phase 1; the classifier reads the posting itself, so a wrong company mapping cannot produce a wrong eligibility verdict, only an off-topic board.

**2026-10-08. GitHub Actions versions pinned to exact tags.** `astral-sh/setup-uv` no longer publishes floating major tags.

**2026-10-08. Release `data-latest` is created with `--latest=false`.** It holds data, not code, and should not show as the repo's latest release.

**2026-10-08. `stats` keyword counts use substring LIKE.** "mena" was dropped because it matched "Blumenau". Phase 2 uses word-boundary regex and Claude, not these counts.

**2026-10-08. Pruned 16 noisy top-up boards (343 to 327).** Rule, in `seed.noise()`, applied only to `ats-scrapers` top-ups: under 5% remote-looking jobs, or 50+ jobs with under 10% unique titles (template spam such as AO Garcia Agency, 3503 jobs and 254 titles). remoteintech boards are exempt because their location text often omits "remote" even when the posting is remote. `seed prune` re-applies the rule from the database without network.

**2026-10-08. Boards removed from the seed list are retired and their jobs expired.** Unlike a fetch failure, removal is deliberate, so expiring is correct.

**2026-10-08. Phase 2 on Gemini instead of Claude.** The Anthropic account has no credit; Google AI Studio has $5. `gemini-2.5-flash-lite` is closed to new users, so the default is `gemini-3.1-flash-lite` ($0.25 in, $1.50 out per million tokens; Batch half). Plain REST through httpx, no SDK. Everything except `gemini.py` is provider-agnostic.

**2026-10-08. No prompt caching.** The system prompt (about 1k tokens) is below the implicit caching minimum, and explicit caching adds storage fees for no gain at this size.

**2026-10-08. Excerpts instead of full descriptions.** Full descriptions would have cost about $3.70 for the backfill in Batch mode. The excerpt keeps the opening (role, seniority) and every paragraph with eligibility keywords. Real usage in the trial: about 1,130 input and 170 output tokens per posting.

**2026-10-08. Extraction schema additions.** `timezone_utc_min` and `timezone_utc_max` (numbers) next to the free-text `timezone_requirement`, so the verdict function never parses text. Regions are a fixed enum.

**2026-10-08. Verdicts are computed, not stored.** Only extractions are stored (one per `content_hash`). The verdict function runs at export time, so tuning it or adding a country costs nothing.

**2026-10-08. Verdict rules, cautious by design.** Explicit exclusion, on-site or hybrid elsewhere, required work authorization elsewhere, a country list without ours, a region list without ours, or a time zone window that misses our offset: not_eligible. Our country listed: eligible. Worldwide: eligible. A region that contains ours, or a time zone window that contains our offset: likely. Remote with no location rule: unclear. A low-confidence extraction is capped at likely, and an evidence quote that is not verbatim in the posting forces low confidence.

**2026-10-08. Daily classification uses the Batch API.** Half price; the workflow waits up to 30 minutes for results, otherwise the next run collects them. The live API reports `BATCH_STATE_*` states while the docs say `JOB_STATE_*`; the code matches on the suffix.

**2026-10-08. Eval set labelling is blind.** `evalset sample` writes labels and predictions to separate files, so whoever labels does not see the model's answer. The sample oversamples eligible and likely predictions, because their precision is what users feel.

**2026-10-08. Eval set drafted by Claude, blind.** 200 labels written from the postings before looking at predictions; marked "draft label by Claude (AI), needs human review". Scores were then used to tune the prompt and the verdict function, so they overstate generalisation until a fresh set is labelled.

**2026-10-08. Location field beats region words and slogans.** Prompt rule: a specific city or country in the location field sets the scope, even for remote roles; a region mentioned as a sales territory is not a hiring region. Re-classified 712 postings. "Unclear" predictions that were really US-only dropped from 24 to 3.

**2026-10-08. "Worldwide" needs role-level evidence.** Deterministic rule in `verdict.py`: worldwide is accepted only when the location field says so or the quote is about this role ("this position", "any country", "location: ..."). A company slogan ("we're a natively remote company") gives "unclear". Eligible precision on the eval set went from 84% to 94%, and every remaining eligible error is a "likely".

**2026-10-08. Reasons in English and French from the same templates**, with French article forms per country in `config.COUNTRIES` ("la Tunisie", "au Maroc").

**2026-10-08. Site: Astro 7.3.4, no client framework.** Pages are fully rendered at build time from the exported JSON; one small script filters rows by data attributes and keeps the filter state in the URL. Pinned to 7.3.4 rather than the release from the day before.

**2026-10-08. Visual direction: professional, not themed.** The owner asked for a professional product with the best UX and UI. A themed direction (station departure board) was considered and dropped. DESIGN.md records the system: navy shell, Public Sans, shape-coded verdict lamps, evidence quote in every row.

**2026-10-08. Unclear jobs are hidden by default but one tap away.** Eligible and Likely show first; the status line says how many Unclear jobs are hidden and offers to show them. Not-eligible jobs are never shown.

**2026-10-08. A quote that is only a company slogan is not shown as evidence.** The row then shows the location field the verdict actually rests on.

**2026-10-08. Listed regions beat "anywhere" text.** When a title or location field names regions ("AMERICAS - Remote") and the text says "anywhere in the world", the verdict is Likely when a listed region includes the country, otherwise Unclear with a reason naming the conflict. Found by the independent design review on the home page sample. Eval eligible precision: 98% (still tuned on the same set).

**2026-10-08. Signups and error reports go to Cloudflare Pages Functions + D1** (owner's choice). `site/functions/api/` validates input, uses a honeypot field, reads the country list from the exported `meta.json`. Live from Phase 4.

**2026-10-08. Hosting: Cloudflare Pages project `hireshere` + D1 database `hireshere`** (binding `DB`, config in `site/wrangler.jsonc`). Deploys use an account API token (Pages Edit, D1 Edit, Account Settings Read) stored as `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` GitHub secrets; browser OAuth (`wrangler login`) hung on the owner's laptop. The daily workflow now runs fetch, classify (batch), export, build and deploy in one job.

**2026-10-08. D1 schema applied with `--command`, not `--file`.** `wrangler d1 execute --file` uploads through a separate endpoint that failed with "fetch failed" from this network; the schema is small enough to send inline.

**2026-10-08. One source of truth for data: the `data-latest` release.** Local classification runs (the 712-posting re-run) were merged into the release database by content hash, newest extraction wins. From now on, download the release before working locally and upload after, so CI and local never diverge.

**2026-10-08. CI builds the site from an empty export** so a broken page cannot ship even though real data is never committed.

**2026-10-08. hireshere.app on Cloudflare DNS.** Bought at Name.com, nameservers moved to Cloudflare (zone on the same account). Apex and www are CNAMEs to hireshere.pages.dev, attached to the Pages project. A Pages Functions middleware 301-redirects www and the pages.dev host to the apex so there is one canonical address; per-deployment preview URLs are untouched.

**2026-10-09. Unknown paths return a real 404.** Without `404.html`, Cloudflare Pages served the home page with 200 for any address (bot scans, `/robots.txt`). Added a 404 page plus generated `robots.txt` and `sitemap.xml` (both built from the site URL, so the domain stays in one place).

**2026-10-09. Email alerts through Resend's free tier** (owner's choice of a free provider). Cloudflare Email Sending needs Workers Paid (about $5/month). Resend free: 3,000 emails/month, 100/day, so the sender stops at 95 a run and the rest go out next run. `pipeline/alerts.py` reads subscribers from D1 through the REST API, sends each one the eligible/likely jobs first seen since their last digest (or signup), then records `last_sent_at`, so a missed day catches up and nothing is sent twice. Unsubscribe links carry HMAC-SHA256(email) with `UNSUBSCRIBE_SECRET`, verified in `site/functions/api/unsubscribe.js`; both the link and the RFC 8058 one-click header are supported.

**2026-10-10. Getting-paid guide per country, sourced, with a disclaimer.** One bilingual (later trilingual) page summarising public sources on receiving foreign pay in TN, MA, DZ, EG (Payoneer, Wise, bank rules, auto-entrepreneur status, the 2026 Tunisian freelancer bill). Each country lists its sources and the page carries a "last checked" date. Most sources are payment-provider blogs, so the text stays at the level they agree on and sends readers to an accountant for status and tax. Linked from every job page.

**2026-10-10. More sources: Workable, Recruitee, Teamtailor, Remote OK.** The three hiring systems publish public per-company JSON (Workable widget API, Recruitee offers API, Teamtailor JSON Feed with schema.org JobPosting); 90 of 450 sampled companies passed validation. Remote OK's API terms allow reuse if we name Remote OK and link back with a followed link, so its jobs credit it as the source and Apply goes to its page (apply links no longer use `noreferrer`). Remotive and Himalayas were not added: both APIs ask not to submit their jobs to third-party job sites, which this is.

**2026-10-10. Arabic (RTL) version under /ar.** Same pages and English URL slugs, `dir="rtl"`, Arabic interface strings (`site/src/i18n-ar.ts`), Arabic verdict reasons (`REASONS_AR` in verdict.py, exported as `reason.ar`) and Arabic email digests. Latin digits (`ar-u-nu-latn`). The employer page stays English inside the Arabic site (its readers are employers). The translation is a draft by Claude and needs a native review. Language switch now shows the two other languages.

**2026-10-10. Redesign: one job search with filters, Ocean palette.** The owner rejected four decorative directions and a minimal one, and picked a classic job-search layout modelled on APEC: search band, filter sidebar with counts, job cards. Countries stopped being tabs and became a filter, so one page (`/jobs`) replaces the four country boards and their field pages; old URLs 301 to the search with the same filters. Palette "Ocean" (deep blue-teal #0B3A53, coral #FF7A59), font Roboto. A review of the mockup fixed inconsistencies that also apply to the live site: the home total counts unique jobs (358), not the sum of country totals (1,354); facet counts always add up to the result count; "Found", not "Posted"; contract wording is Employee/Contractor everywhere; the card verdict line follows the selected countries ("Eligible in Tunisia, Egypt").

**2026-10-11. Worldwide: every country gets a verdict (owner's decision of 2026-10-10).** All remote, hybrid and unclear jobs with an extraction are listed (7,956 of 16,634 open postings today); office-only jobs stay out. Verdicts for 243 countries (`data/countries.json`) are computed at export from the stored extractions, so this cost no model calls and the classifier and pre-filter are unchanged. A country fits a time zone window when its UTC offset range overlaps it; the four featured countries keep their single offset and regions, so their verdicts did not move. French reasons now name the country without an article ("Tunisie figure parmi les pays acceptés"). Each job stores its verdicts as groups of countries sharing an outcome, reasons carry a "{c}" placeholder for the localized name, and "*" stands for every country not listed elsewhere (used when the most common outcome is shown; only then are exclusions listed). The site cannot prerender 8,000 jobs in 3 languages under the free plan's 20,000-file limit, so job pages are rendered by a Pages Function from 256 detail shards into a static shell, and cards are drawn in the browser from a per-language search index (about 500 KB gzipped). The visitor's country comes from `?c=`, then their last choice, then Cloudflare's `request.cf.country`. Alerts accept any country; Telegram stays on the four featured channels; the getting-paid guide is linked for the featured countries only.

**2026-10-11. Brand identity and plain-language verdicts.** After a critique against Welcome to the Jungle, We Work Remotely, Wellfound and Working Nomads (the site had no imagery, a template logo and verdicts that read like classifier output), the owner approved a clickable mockup and it was built into the site: pin-and-check logo, Bricolage Grotesque and DM Sans, warm paper ground, photo collages, a world map coloured by real job counts, a "Your country" select in the header, cards with one verdict pill, a job page led by "You can apply from <country>", and About and Contact pages (email, phone/WhatsApp, Telegram channels marked "coming soon" until their public links exist). Verdict reasons were rewritten in plain words in EN/FR/AR ("The required hours (UTC-1 to UTC+3) work from Tunisia"). The world map is a static SVG generated once, so no mapping library ships to visitors.

**2026-10-11. Posting dates, every level treated alike, Jobicy, junior-friendly companies (owner's request).** Every connector now stores the employer's own posting date (`posted_at`: Greenhouse `first_published`, Lever `createdAt`, Ashby `publishedAt`, SmartRecruiters `releasedDate`, Recruitee `published_at`, Teamtailor `datePosted`, Workable `published_on`, Remote OK and Jobicy `date`/`pubDate`). The first fetch showed why it matters: of 16,628 open jobs, 1,671 were posted in the last 7 days and 7,778 more than two months ago (some in 2016, evergreen talent pools), while "first seen" made them all look a few days old. Cards and job pages now say "Posted n days ago" (falling back to "Found" when a feed gives no date), sort by it, offer a "Last 30 days" filter, and draw postings older than 60 days muted. Email alerts and Telegram only announce jobs posted in the last 14 days, so a newly added company's old postings are not sent as news. The pre-filter no longer drops hybrid jobs (the site already lists hybrid; 1,550 were being skipped) or intern, junior, graduate, trainee, stage and alternance titles that name only a city, unless the feed flags them office-only; skipped jobs are re-checked every run, so a pre-filter change applies to old jobs too. One-time cost about $0.75 in batch mode. Jobicy's public API was added (its terms allow reuse with a credit and a link, and Apply goes to the Jobicy page, like Remote OK); its feed only lists the last 7 days, so its jobs expire 30 days after posting rather than when they drop out (`config.ROLLING_DAYS`). LinkedIn, Indeed and Glassdoor stay out (their terms forbid automated collection), as do Remotive and Himalayas (see 2026-10-10), Arbeitnow (no published terms) and The Muse (terms page unreachable). 162 companies were added from a sample of 2,800 ats-scrapers boards, chosen for intern, junior and graduate openings that pass the pre-filter, capped at about 3,000 postings to classify (`source_of_entry = ats-scrapers+entry`); `seed.noise` now keeps a board with two or more such openings even when few of its jobs say remote. Company pages list every level they hire for, and the companies index marks intern and junior roles.

**2026-10-11. Free-tier classification (owner has no budget).** The prepaid Gemini credit ran out (HTTP 402 at batch submit). Classification now runs in sync mode on free tiers: a Gemini key from a project without billing (`gemini-3.1-flash-lite`, paced at 10 requests a minute) and, once Gemini answers with its daily quota error, Groq's free tier (`openai/gpt-oss-120b`, structured JSON output, 4 a minute) for the rest. At most 500 postings and 35 minutes per run; whatever is left stays pending for the next run, and an out-of-credit or quota answer never fails the daily job. A spot check on 8 live postings: free Gemini matched the stored paid extractions on every field; Groq matched the allowed countries on all 8, remote type on 7 and seniority on 6, so it is the fallback, not the default. Each extraction records the model that made it. Batch mode stays in the code for when billing returns.

**2026-10-12. Functions only where needed.** Job pages went down: with no `_routes.json`, `_middleware.js` ran on every request (assets, shards, logos), so the free plan's 100k daily Function invocations ran out and Pages "failed open" to static files. `_routes.json` now limits Functions to `/jobs/*`, `/fr/jobs/*`, `/ar/jobs/*` and `/api/*`. Old country boards became static `_redirects`; the www redirect is a Cloudflare Redirect Rule set in the dashboard. If Functions are ever off again, `_redirects` serves the job shell and the shell renders the job in the browser from its detail shard. The daily workflow retries a failed Pages deploy once and uploads the database whenever fetch succeeded, so a deploy error no longer loses a day of fetching and classification.

**2026-10-13. Every 4 hours, newest first, a welcome email.** On free tiers the run's time is the AI pacing (35 of 38 minutes), so the pipeline now runs every 4 hours (`17 */4 * * *`) with 15 minutes of classification each: new jobs show within hours instead of once a day, GitHub's late starts matter less, and Groq gets about 90 minutes a day instead of 35. Gemini and Groq work the queue at the same time, newest jobs first (the oldest-first queue had left 582 of 602 new jobs waiting and alerts empty). Email digests still go out at most once a day per subscriber (`MIN_HOURS_BETWEEN = 20`) and count a backlog job from when it was classified. New subscribers get a welcome email from the sign-up Function (`site/functions/api/_welcome.js`, Resend, sent after the reply so a failure cannot break sign-up); `RESEND_API_KEY` is now also a Pages secret. Site copy says "several times a day" instead of "every morning".

**2026-10-13 (later). Back to once a day, published early.** The owner wants one run a day. The run now publishes the fresh fetch right after fetching (export, build, deploy: about 3 minutes in), then spends up to 35 minutes on free-tier classification, then publishes again with the new jobs and sends alerts. Newest-first and the two providers in parallel stay. The once-a-day digest guard stays too (it also stops a manual re-run from emailing twice). Site copy says "every day".
